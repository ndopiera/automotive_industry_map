# Automotive NRW – Verwaltung V3

## Lokal starten
ZIP entpacken. Arbeitsdatenbank unter 01_Database/automobilbranche_nrw_work.db lokal aufbewahren (durch .gitignore ausgeschlossen), alternativ außerhalb des Repos. Start_Windows.bat doppelklicken (Python erforderlich), alternativ Start_macOS_Linux.sh oder `python -m pip install -r requirements.txt` und `python -m streamlit run app.py --server.address localhost`.
Links den Pfad der bestehenden Datenbank auswählen. Beim ersten Öffnen wird eine Sicherung `_vor_v3.db` angelegt und die Struktur erweitert. Bestehende Unternehmen erhalten TEST, neue DRAFT. Die Originaldatei wird ab diesem Zeitpunkt durch die Maske bearbeitet. Keine zweite Migration nötig. Die Größenklasse ID 5 und das Land DE sind weiterhin Standardwerte.

## GitHub einmalig vorbereiten
Die nummerierte Struktur nach README übernehmen. Keine Arbeitsdatenbank, Backups oder Token hochladen. Der neue Exporter erwartet eine öffentliche V3-Datenbank. Beim Umstellen daher die öffentliche DB zusammen mit den beiden Dateien in einem Commit hochladen, oder zuerst öffentliche DB, dann die zwei Dateien. Im Repository muss die öffentliche DB `01_Database/automobilbranche_nrw.db` heißen. Alte öffentliche Daten können weiterhin in der Git-Historie liegen.

## Veröffentlichung
In der Maske unter Veröffentlichung Testfreigaben bewusst einschalten, solange die Testkarte benötigt wird. Standardmäßig werden ausschließlich APPROVED exportiert. Die öffentliche DB wird frisch aufgebaut; Prüfhistorie, interne Quellnotizen und Herkunft werden nicht exportiert. Alle übrigen Unternehmens-/Quellenfelder sind öffentlich: keine vertraulichen Inhalte dort speichern. Bei manueller Veröffentlichung Download im Repository in `01_Database/automobilbranche_nrw.db` umbenennen. Beim automatischen Upload übernimmt die Maske den Dateinamen. Fine-grained GitHub Token nur für dieses Repository: Contents read/write, Actions read (für Status) bzw. read/write (für manuellen Start). Token lokal in der Maske eingeben, niemals committen. Push auf main löst Workflow aus; nicht zusätzlich starten. Status separat aktualisieren. Keine automatische Veröffentlichung bei Dateneingabe.

## Stammlisten und Freigaben
DE/EN, Codes, Größenintervalle, Elternkategorie pflegen. IDs bleiben bei Bearbeitung gleich. Fremdschlüssel blockieren Löschen verwendeter Einträge. Verschieben verwendeter Unterkategorien ist gesperrt. Änderungen an freigegebenen Unternehmen oder zugehörigen Daten setzen Status auf PENDING. Die Prüfhistorie dokumentiert Entscheidungen, Kürzel, Datum, Checkliste und optionale Dauer. Keine Benutzeranmeldung: lokaler Einzelanwender-Prototyp, kein manipulationssicheres Audit-System. Freigabe auf Unternehmensebene. Neue SQL-Importe sind DRAFT und können einzeln zur Prüfung gestellt werden. Größenintervalle werden auf gültige Grenzen geprüft, nicht auf lückenlose/überlappungsfreie Gesamtsystematik.

Neue Hauptkategorien bekommen automatisch zusätzliche GeoJSON-Felder, Kategorie-Dateien und Farben; neue Einzelkategorien nutzen ein generisches Fragezeichen-Symbol. Neue Filter in uMap manuell ergänzen. Alte Kategorien-Dateinamen bleiben erhalten. Teststatus steht im GeoJSON als review_status. uMap auf die neue Repository-URL umstellen. Die veröffentlichten Daten sind ein Snapshot; Rücknahmen werden erst mit der nächsten Veröffentlichung wirksam.
